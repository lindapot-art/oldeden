FINDING 1.5 — loadFromServerData() uses Object.assign for nested objects
  Severity: MEDIUM

  CURRENT CODE:

    REVISED — Object.assign behavior is correct for this use case.
    NOT A BUG for the current migration approach.

FINDING 2.1 — Socket disconnect doesn't save game state
  Severity: HIGH
  Lines: 1892-1905 (connectSocket)

  CURRENT CODE:
    s.on('disconnect', () => {
      state.connected = false;
      updateServerStatus(false);
    });

  PROBLEM:
    When the socket disconnects (server restart, network drop), the
    player's progress since last auto-save (up to 60 seconds) is lost
    on the server side. The client still has the state, but an
    immediate saveGame() call would fail because the socket is dead.
    The localStorage save should be triggered on disconnect as safety.

  FIX:
    s.on('disconnect', () => {
      state.connected = false;
      updateServerStatus(false);
      // Emergency save to localStorage on disconnect
      try { localStorage.setItem('oe-save', JSON.stringify(saveGame())); }
      catch(e) {}
    });

    Actually, saveGame() already saves to localStorage AND emits to
    socket. The socket emit will silently fail when disconnected. So:

    s.on('disconnect', () => {
      state.connected = false;
      updateServerStatus(false);
      saveGame(); // localStorage will succeed, socket emit will silently fail
    });


FINDING 2.2 — combat:kill emit has no offline fallback for credits
  Severity: MEDIUM
  Lines: 6953-6954 (kill emit), 6921-6923 (credits update)

  CURRENT CODE:
    state.player.credits += Math.floor(pts * 0.4);
    // ...
    if (state.socket) state.socket.emit('combat:kill', { enemyType: e.type, points: e.points });

  COMBINED WITH (line 1922-1926):
    s.on('combat:rewarded', (data) => {
      if (data.wallet) {
        state.player.credits = data.wallet.ec;
        state.player.stellarMarks = data.wallet.sm;
      }

  PROBLEM:
    The client adds credits locally (line 6921), then the server
    responds with the AUTHORITATIVE wallet balance (line 1924). If the
    server is laggy, the player sees credits spike up locally then drop
    when the server overwrites with a potentially different number.

    Worse: if the player is offline, they accumulate credits locally.
    When they reconnect and load from server, their offline credits are
    wiped by the server's stale wallet balance.

  FIX:
    Use a "pending credits" approach: track credits earned offline
    separately and reconcile on reconnect. Or simpler: don't overwrite
    credits from server if the server balance is LOWER than client
    balance (indicating stale server data).

    Quick fix in combat:rewarded handler:
      if (data.wallet) {
        // Only accept server wallet if it's higher (server has newer data)
        state.player.credits = Math.max(state.player.credits, data.wallet.ec);
        state.player.stellarMarks = Math.max(state.player.stellarMarks, data.wallet.sm);
      }

    }
