BUG 2.1 — Ambience has no gain node — volume cannot be controlled
─────────────────────────────────────────────────────────────────────────────────

Location: Lines 1042–1052 (AudioSFX.startAmbience)

Code:
  startAmbience() {
    if (!this.ctx || this.ambience) return;
    this.ensure();
    const ctx = this.ctx;
    const buf = ctx.createBuffer(1, ctx.sampleRate * 4, ctx.sampleRate);
    const d = buf.getChannelData(0);
    for (let i = 0; i < d.length; i++) d[i] = (Math.random() * 2 - 1) * 0.008;
    const src = ctx.createBufferSource(); src.buffer = buf; src.loop = true;
    const filt = ctx.createBiquadFilter(); filt.type = 'lowpass'; filt.frequency.value = 300;
    src.connect(filt); filt.connect(ctx.destination); src.start();
    this.ambience = src;
  },

Problem:
  Unlike BGM (which uses a masterGain node) and engine hum (which uses a gain
  node), the ambience path connects: src → filter → destination with NO
  intermediate GainNode. This means:
  1. Ambience volume cannot be adjusted at runtime (masterVol/sfxVol settings
     are ignored for ambience).
  2. The ambience plays at the fixed hardcoded amplitude (0.008 * random)
     regardless of user volume settings.
  3. There is no way to fade out ambience gracefully — `stopAmbience()` does an
     abrupt `.stop()` which can cause an audible click/pop.

Fix:
  Add a GainNode between filter and destination, scaled by settings:

  startAmbience() {
    if (!this.ctx || this.ambience) return;
    this.ensure();
    const ctx = this.ctx;
    const vol = state.settings.masterVol * state.settings.sfxVol;
    const buf = ctx.createBuffer(1, ctx.sampleRate * 4, ctx.sampleRate);
    const d = buf.getChannelData(0);
    for (let i = 0; i < d.length; i++) d[i] = (Math.random() * 2 - 1) * 0.008;
    const src = ctx.createBufferSource(); src.buffer = buf; src.loop = true;
    const filt = ctx.createBiquadFilter(); filt.type = 'lowpass'; filt.frequency.value = 300;
    const gain = ctx.createGain(); gain.gain.value = vol;
    src.connect(filt); filt.connect(gain); gain.connect(ctx.destination); src.start();
    this.ambience = { src, gain };
  },
  stopAmbience() {
    if (!this.ambience) return;
    try { this.ambience.src.stop(); } catch(e) {}
    try { this.ambience.gain.disconnect(); } catch(e) {}
    this.ambience = null;
  },

BUG 2.2 — play() leaks orphan GainNode on early-return paths
─────────────────────────────────────────────────────────────────────────────────

Location: Lines 964–1030 (AudioSFX.play, cases: karma_rare, karma_legendary,
          karma_accept, hull_hit, loot_fuel, reload)

Code (example — karma_rare, line ~975):
  play(type) {
    ...
    const gain = ctx.createGain();
    gain.connect(ctx.destination);       // ← gain connected to output
    const osc = ctx.createOscillator();
    osc.connect(gain);
    switch(type) {
      ...
      case 'karma_rare': {
        const o2 = ctx.createOscillator();
        ...
        o2.connect(gain);
        ...
        o2.start(now); o2.stop(now+0.8);
        osc.disconnect();                // ← osc disconnected
        return;                          // ← gain never disconnected
      }

Problem:
  Six sound types follow a pattern of: create gain → create osc → switch case
  creates a DIFFERENT source (o2, src, etc.) → connects new source to gain →
  `osc.disconnect(); return;`. The original `osc` is disconnected from `gain`,
  but `gain` remains connected to `ctx.destination`. The replacement source
  (o2, src, etc.) is scheduled to stop, and once it stops, WebAudio will
  eventually collect the chain. However, until the browser's GC runs, the gain
  node is an orphaned live connection to the audio destination.

  In rapid fire scenarios (e.g., collecting many loot drops quickly, each
  triggering loot_fuel or hull_hit), dozens of orphan GainNodes accumulate on
  `ctx.destination`. While WebAudio spec says they're eventually collected
  after all connected sources end, the timing is implementation-dependent.
  On Safari (WebKit), these can persist for several seconds, causing audio
  artifacts when many GainNodes sum into the destination.

Fix:
  Disconnect osc AND gain before returning, or don't create osc at all for
  buffer-source sound types. Simplest fix — don't connect osc for cases that
  don't use it:

  // At top of play():
  const gain = ctx.createGain();
  gain.connect(ctx.destination);
  // Only create+connect osc for cases that use it
  let osc = null;
  // ... in each case that needs osc:
  //   osc = ctx.createOscillator(); osc.connect(gain);
  // ... in cases that DON'T need osc (hull_hit, loot_fuel, reload, etc.):
  //   just use buffer source directly, no orphan osc

  Alternative (minimal change): in the early-return cases, add gain cleanup:

  case 'hull_hit': {
    const dur=0.12; ...
    src.start(now);
    src.onended = () => { gain.disconnect(); };
    return;
  }

  2. Third listener toggles chatbot panel open
  3. Pointer lock exits, chatbot input focuses after 100ms
  4. Player releases T → keyup removes 't' from keysDown
