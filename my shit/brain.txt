Screenshot-first gameplay workflow

- Use long visual runs as the truth source, not diff confidence.
- Treat mobile as a first-class path: no forced pointer lock, touch move plus touch aim, gyro tilt steering, compressed HUD, larger taps.
- Use real local soundtrack assets when they exist: serve them directly, make the opening track explicit, and tie the player volume into the existing BGM control.
- When QA says green but the screenshots still feel bad, trust the screenshots and keep drilling.
- Ship fixes in batches: reproduce, patch, run visual QA, run full QA, then commit.
- Keep generated screenshot evidence out of the code commit unless it is explicitly requested.
